# Diff UI spec

## Metadata
- **Spec ID**: `20260410-1l07`
- **Feature name**: `awp diff UI`
- **Owner**: AI coding agent
- **Status**: Done
- **Last updated**: 2026-04-10

## Goal
Give users a polished, daily-driver diff viewer for the current Jujutsu repo so they can review changed files and hunks, refresh quickly, search, and jump directly into their editor at the relevant changed line.

## User Problem
The user wants the "nice diff viewer" experience from an earlier prototype, but adapted to the current awp redesign. Today awp has workspace lifecycle commands and some Bubble Tea UI pieces, but no dedicated review UI. Reviewing changes currently requires bouncing between raw `jj diff`, ad hoc editor commands, and manual navigation. That is slower and less pleasant than a purpose-built TUI.

## Scope
### In scope (v1)
- Add a new top-level command: `awp diff`.
- Run the diff viewer against the **current repo / current working copy** only.
- Launch directly in the current terminal session (not via tmux-managed panes/windows).
- Show a changed-files list and hunk preview.
- Support keyboard navigation for files and hunks.
- Support opening the selected file/hunk in `$EDITOR` (or editor fallback) at the relevant changed line.
- Support filtering/searching the changed file list.
- Support manual refresh.
- Support manual refresh for a polished daily-driver experience.
- Handle common diff cases well: modified files, new files, deleted files, renames, and empty diff state.
- Add/update automated tests for parser, UI model behavior, editor command generation, and CLI wiring.

### Out of scope (v1)
- Tmux-managed embedding or automatic pane/window creation.
- Multi-workspace/session browsing.
- Interactive patch editing/staging/reverting from the TUI.
- Side-by-side diff rendering.
- Git support outside jj repos.
- Persisted UI preferences/history.
- Inline comments, PR review actions, or code-ownership metadata.

## UX
### CLI
- New command: `awp diff`
- Running `awp diff` outside a jj repo returns an actionable error.
- Running `awp diff` inside a jj repo opens a full-screen Bubble Tea TUI.
- No workspace argument is supported in v1; the command operates on the current repo context.

### TUI
- Header shows that the user is in the awp diff UI and indicates the current repo/workspace context where practical.
- Left panel lists changed files.
- Right panel shows the selected file's hunks.
- Footer/help shows keybindings and refresh status.
- Required interactions:
  - `j/k` and arrow keys move through files/hunks
  - `tab` switches focus between files and hunks; `h`/`l` and left/right also switch focus between panels
  - `enter` or `e` opens the selected file or hunk in the editor at the changed line
  - `/` enters filter mode for file search
  - `r` refreshes the diff immediately
  - `r` refreshes the diff immediately
  - `q` quits
- Empty state clearly indicates when there are no changes.
- Errors are visible but non-destructive when possible (for example, refresh failure should not crash the program).

## Discovery Questions
1. Who is the first user? Andrew, working inside jj repos and wanting a polished review workflow in awp.
2. When do they use this feature? During normal coding/review loops, after making changes or while inspecting in-progress work.
3. What exact output/result do they need? A full-screen diff browser with fast keyboard navigation and one-keystroke jump into the editor.
4. What data sources are required? `jj diff --git` for detailed hunks, current repo detection from `jj root`, and environment/editor configuration from `$EDITOR`/fallback behavior.
5. What is the smallest useful slice? `awp diff` for the current repo with file list, hunk preview, editor jump, filter, and refresh.
6. What are explicit non-goals? Tmux integration, multi-workspace scope, and patch-manipulation features.
7. What does “done” look like? A stable top-level `awp diff` command that feels polished enough for daily use in the current repo.

- 2026-07-30: The viewer is no longer reachable only as a bare CLI command — the deck's `c` key now opens it as a `bodyModal` (`internal/deckui/modal_diff.go`) scoped to the selected workspace's working change, injected via `WithDiffViewer`. `C` keeps opening a tuicr window against the stack base. Motivation: the viewer had quietly rotted (highlighting removed, auto-refresh disabled) because nothing in the daily path went through it, while `c` went to tuicr. This is phase 0 of evaluating an awp-native reviewer; **out of scope here**: review comments, sessions, PR mode, GitHub publishing.
- 2026-07-30: To support embedding, `Model` swapped its `height` field for `bodyHeight` plus exported `SetSize` / `Body` / `Status` / `Filtering`, so a host can render the two panes and own the header/footer itself. Standalone `awp diff` sizing is unchanged (`WindowSizeMsg` routes through `SetSize(w, h-chromeHeight)`).
- 2026-07-30: Hunk-pane `j`/`k` now scroll one line instead of moving the hunk cursor — a file with a single large hunk was unscrollable with `j`/`k` while `ctrl+d`/`ctrl+u` worked. Hunk-to-hunk jumping moved to `{`/`}`, and any scroll re-points the hunk cursor at the top visible row so the highlighted header and `e`'s target line track what's on screen. `ensureSelectedHunkVisible` / `selectedHunkRowRange` deleted in favor of `scrollHunks` / `jumpHunk` / `syncHunkCursorToScroll` / `hunkStartRow`.
- 2026-07-30: **Decision: no intra-line highlighting.** It was tried again (character-level via `go-udiff`) and reverted the same day, along with the dependency. Character-level LCS matches letters across unrelated identifiers, producing misleading speckle on code (`m.trigger(ActionOpenWindow, "review")` → `m.openDiffModal()` lit up `trigger(Acti` and `OpenWindow,`). The obvious fix — diffing tokens instead of characters — is a per-language tokenizer, i.e. an open-ended language-support commitment for a rendering nicety. The rendered diff is whatever `jj diff --git` produced, coloured per line, full stop. The goal of this surface is a better **review workflow**, not a better diff renderer than the industry standard; effort belongs in comments/findings/sessions, not here. This closes out the 2026-04-10 "intra-line highlighting" experiment for good — don't re-attempt without a workflow reason.
- 2026-07-30: `enter` removed as an open-file binding; `e` is the only one, in both panes. `enter` on a file row instead moves focus to the hunk pane — same effect as `tab`, but it's the key a two-pane list invites you to press. Filter-mode `enter` (confirm) is unaffected.
- 2026-07-30: Vertical navigation crosses file boundaries: at the hunk pane's bottom, a further `j` / `ctrl+d` moves to the next file's top; at the top, `k` / `ctrl+u` moves to the previous file's *bottom*. Reaching the edge and crossing it are separate presses. **Superseded the same day** — see the continuous-scroll entry below. In use it didn't feel good, and it had a fatal flaw: key repeat is indistinguishable from a deliberate second press (terminals send no key-release events), so holding `j` sailed straight through the boundary. The only fix within that design was a timing heuristic — cross only if ~200ms elapsed since the last navigation key — which was implemented, judged a bad trade (a threshold tuned to one machine's repeat rate, guarding a boundary that shouldn't exist), and abandoned rather than committed.
- 2026-07-30: **The hunk pane became one continuous scroll over the whole diff** (`internal/ui/stream.go`, `internal/ui/stream_render.go`). Every file's hunks render in sequence with an inline file header and a separator row; the file list is now a jump index rather than a selector. There is no file boundary, so boundary crossing and the key-repeat problem both cease to exist. `{`/`}` hop hunks across the entire change; `g`/`G` reach its ends.
  - **Geometry is separated from rendering**, which is what makes a whole-diff stream affordable — and makes it *faster* than the per-file pane it replaces. `streamIndex` answers "how many rows, and what does row N show" while building no strings: one `rowRef` per row (kind, file, hunk, line, wrapped-segment ordinal, and precomputed old/new line numbers), plus per-file header offsets, a flat list of hunk-header rows, and per-hunk gutter widths. Scroll clamping, the file-cursor sync and hunk jumps are lookups. Only the rows actually on screen are styled. The previous design rendered every row of the current file per frame *and* several more times per keypress via `clampHunkScroll` / `syncHunkCursorToScroll` / `maxHunkScroll` / `jumpHunk`.
  - The index is keyed on `(files, width, wrap)` and rebuilt only in `rebuildStream`. The horizontal pan is deliberately **not** an input — it applies to the visible window at render time, so panning never invalidates geometry.
  - **Wrap is now a hard character wrap**, not a word wrap: a line's row count becomes `ceil(width/avail)` arithmetic instead of requiring a trial layout, which is what keeps the geometry pass string-free. Hard wrap also suits code, where reflowing at word boundaries breaks tokens apart misleadingly.
  - Scroll clamps at `len(rows)-1` rather than stopping when the last row reaches the bottom. The tight clamp left a late file's header unreachable, so seeking to the last file landed short of it and the file list pointed at one file while the top row belonged to another. Vim scrolls this way for the same reason; the cost is blank space past the end.
  - The inter-file separator row is attributed to the file it *follows*, so the file cursor changes exactly when the next header reaches the top rather than one row early.
  - Deleted: `layoutHunks`, `hunkLayout`, `hunkAtRow`, `maxHunkScroll`, `advanceFile`, `scrollHunksOrCrossFile`, `syncHunkCursorToScroll`, `hunksCursor`, `selectedHunkStyler`, `renderHunkPanel`, `renderHunkTitle`, `renderHunkLines`, `renderDecoratedLine`.
  - Fixed in passing: `applyFilter` returned early on the empty-filter path, which would have skipped the geometry rebuild on every load.
- 2026-07-30: Fixed a key collision the phased build introduced: the deck modal took `c` as a close key (from when `c` only toggled the view), while the viewer later took `c` as the comment gesture — so the modal closed before the viewer ever saw it and commenting was unreachable from the deck. `c` now belongs to the surface once it is open; `esc` / `q` / `ctrl+c` close. A test had pinned the wrong behavior, which is how it survived. Also: opening a diff now lands the cursor on the first line of **code** rather than the file divider, since every cursor gesture — commenting especially — needs a line rather than a header.
- 2026-07-30: **Live refresh re-enabled** (phase 2 of the review-surface spec), reversing the 2026-04-10 decision to disable it — that was disabled because reloads jumped the cursor, and this fixes the jumping rather than the polling. `DefaultRefreshInterval` is 2s.
  - A reload carries a **fingerprint** of the raw diff text. An unchanged diff is dropped before it touches any view state, which is what makes polling invisible: most ticks change nothing.
  - When the diff *has* changed, the cursor is restored **by content, not by index** (`internal/ui/anchor.go`). Row indices are meaningless across a rebuild — inserting one line above the cursor shifts everything below it. The ladder: same text and same line number → same text at the same *occurrence ordinal* within the file → nearest line number among text matches → nearest line number anywhere in the file → the file's divider. A vanished file falls through to a clamp.
  - Duplicate line content (`}`, blank lines, repeated calls) is ordinary in code, so text matching alone flings the cursor to the first identical line whenever anything above it moves. Ordinal disambiguates where line-number distance cannot: two equidistant duplicates are a genuine tie, whereas "it was the third `}`" survives insertion above.
  - The cursor's **distance from the top of the viewport** is preserved, not merely its visibility. Re-centring or scrolling to an edge would slide the surrounding text under the reader even with the cursor correctly placed.
  - Deliberately a poll rather than an fsnotify watch, which is what the review-surface spec assumed: `jj diff` already costs a subprocess and snapshots the working copy, unchanged results are free via the fingerprint, and watching a tree on macOS means per-directory kqueue watches with no recursive option. Revisit if 2s proves costly.
  - This machinery is the same relocation problem comments need, so phase 3 inherits a tested implementation rather than growing a second one.
- 2026-07-30: Added a **line cursor** (phase 1 of `specs/20260730-4o94-awp-native-review-surface-spec.md`). `cursorRow` indexes `stream.rows`; `j`/`k`, paging, `g`/`G`, `{`/`}` and file seeks all move the cursor, and the viewport follows it with a small lookahead margin instead of being driven directly. The current file is now derived from the cursor row rather than the top visible row, and `e` opens at the cursor's line. Rendering reserves the app-wide `┃ ` selection-prefix columns on every stream row (blank when not the cursor), tints the cursor row's line numbers `Warning`, and draws a vim-style **cursorline**: a `BgPanel` background across the full pane width. That token was the palette's reserved-and-unused background, and a cursor is exactly the "selection treatment where the contrast is intentional" the design system carves out for background fills. Every style used on the cursor row carries the background itself — an enclosing style cannot supply it, because each inner style ends with a reset that would clear it mid-row. The file divider is exempt: it is already a full-width band, so a cursorline behind it would add nothing. Because the prefix narrows content width, `SetSize` subtracts it from the wrap width; otherwise wrapped row counts would disagree with what is rendered. The viewer also now opens with the diff pane focused rather than the file list — reading the change is the point, and the file list is a jump index you reach for second. The cursor is deliberately the whole of this change: it is the anchor both commenting and contextual expansion need, so it lands alone to be judged on its own.
- 2026-07-30: The file divider is drawn as a rule spanning the pane with the filename set into it — `══ M path/to/file.go (3 hunks) ══════…` — after the first version (badge + path only) proved hard to pick out while scrolling. In a continuous stream the file boundary is the primary landmark, so it has to be unmissable. The rule glyph is `═`, not `─`, because the pane already sits inside a rounded `─` border and a single rule reads as more border rather than a section break. The rule and filename carry `Accent`, switching to `Warning` for the file the cursor is in (per the design system: structural headers take the accent, selection takes the warning hue); the hunk count stays muted. `renderPath` gained a `renderPathWith` variant taking explicit dir/base styles so the divider gets its own hue without re-implementing rename-arrow splitting and truncation, and the style choice is factored into `fileRuleStyles` so it can be asserted in tests — lipgloss strips colour with no TTY, so rendered output can't carry that assertion.
- 2026-07-30: Fixed inverted emphasis in the file list. Unselected basenames were bold (`stylePathBase`) while the selected row's were not (`styleSelectedPathBase` set colour only), so the cursor row read as *less* emphasized than its neighbours; the outer `styleSelected.Width` wrap in `renderFileList` couldn't compensate, because `renderFileRow` had already emitted per-segment ANSI attributes and an enclosing style can't add bold to text that already declared its own. Selected segments are now `Warning` + bold, the dead outer wrap is gone, and the file list picked up the `┃ ` left-bar prefix the design system specifies for every list/picker/overlay (unselected rows reserve the same two columns, so labels stay aligned).
- 2026-07-30: Pane focus moved to `tab` / `shift+tab` (toggling both directions; previously `tab` only went files → hunks and `h`/`l` carried the switch), freeing `h`/`l` to pan the hunk pane horizontally by `hScrollStep` (8) columns. The offset applies to line *content* only via `ansi.TruncateLeft`, so line numbers and the `+`/`-` gutter stay pinned and a panned line is still identifiable. Clamped so `minVisibleColumns` (16) of the longest line stays on screen, with `0`/`home` and `$`/`end` jumping straight to either bound (vim semantics). Panning is meaningless under wrap, so `h`/`l` no-op there and enabling wrap zeroes the offset. Changing the selected file resets scroll, pan and hunk cursor together via `resetHunkView` — previously three separate assignments at five call sites, one of which would have carried a pan into the next file.
- 2026-07-30: `w` toggles soft line wrap in the hunk pane (default off, i.e. today's truncation). Wrapping breaks the "one row per hunk line" assumption the scroll math rested on, so `totalHunkRows` / `hunkStartRow` were replaced by a single `layoutHunks` pass returning the rendered rows plus each hunk's header row index; `renderHunkPanel`, `clampHunkScroll`, `syncHunkCursorToScroll` and `jumpHunk` all derive from it, so rendered geometry and scroll geometry can't drift. `renderDecoratedLine` now returns `[]string` (continuation rows indented under the code, gutter column left clean), and `Model` caches `hunkWidth` from the shared `paneWidths` helper so the update path lays out at the render width.

## Implementation Plan
1. Add jj adapter support for obtaining git-format diff output for the current repo context, with explicit, testable command behavior.
2. Add a diff parser package/model that converts `jj diff --git` output into file/hunk structures with changed-line mapping for editor jumps.
3. Add an editor adapter that resolves `$EDITOR`/fallback behavior and constructs commands for opening files at a given line.
4. Add a Bubble Tea diff UI package with:
   - file-list focus
   - hunk-list focus
   - filter mode
   - manual refresh
   - auto-refresh
   - clear status/error rendering
5. Wire `awp diff` into the existing CLI app as a top-level command.
6. Add tests for CLI command behavior, jj command generation, diff parsing edge cases, editor command generation, and UI model interactions.
7. Polish copy, empty states, and error messages so the feature is suitable for daily use.
8. Keep refresh behavior predictable; prefer manual refresh over disruptive background updates.
